# Protocol 767 (Minecraft 1.21.1): packets the bot uses

Ids come from reports/packets.json (generated by the server's own data generator); field orders from the packet codecs
(read in the decompiled server). Wire types: VarInt = LEB128; Position = one big-endian long, x 26 bits << 38 | z 26 bits << 12 | y 12 bits;
Direction / Hand / enum = VarInt ordinal (Direction: down 0, up 1, north 2, south 3, west 4, east 5; Hand: main 0, off 1);
strings = VarInt byte length + UTF-8; UUID = two longs; bool = 1 byte; Component in play/config = network NBT (unnamed root), in login-disconnect = JSON string.
Frame: VarInt length | (if compression on: VarInt dataLength, 0 = uncompressed) | VarInt id | body. Compression applies to packets whose id+body length is >= threshold.

## 2. Packet layouts

Handshake intention (S 0): protocolVersion VarInt (767), host string (max 255), port unsigned short, intent VarInt (1 status, 2 login, 3 transfer).

Status: request has no body; response = JSON string.

Login:
- hello (S 0): name string (max 16, only chars 33..126 allowed), UUID. Offline mode: the server IGNORES the client's UUID and uses the offline UUID
  (MD5 of "OfflinePlayer:" + name as a type-3 UUID) from the name.
- login_compression (C 3): threshold VarInt (server default 256; sent before game_profile).
- game_profile (C 2): UUID, name (max 16), property list (VarInt count max 16; each: name, value, optional signature), boolean strictErrorHandling.
- login_acknowledged (S 3): empty; switches both directions to configuration. Login must finish within 600 ticks.
- login_disconnect (C 0): JSON string.

Configuration:
- Server sends custom_payload (brand), optional server_links, update_enabled_features, then select_known_packs (C 14: VarInt count, each namespace, id, version).
- Client must answer select_known_packs (S 7, same list type, max 64). An empty list makes the server send the full registry_data (C 7) and update_tags (C 13).
  Until answered the server never sends finish_configuration.
- finish_configuration (C 3, empty) -> client sends finish_configuration (S 3, empty), then the connection is in play.
- client_information (S 0, optional): language string (16), viewDistance byte, chatVisibility enum VarInt, chatColors bool, modelCustomisation unsigned byte, mainHand enum VarInt,
  textFiltering bool, allowsListing bool. If never sent the server uses defaults: viewDistance 2 (also the minimum), language en_us.
- keep_alive (C 4 / S 4): one long. ping (C 5) -> pong (S 5): one int.
- disconnect (C 2): network NBT component.

Play, serverbound:
- accept_teleportation (0): VarInt id.
- move_player_pos (26): x,y,z doubles, flags byte (bit 0 onGround). pos_rot (27): x,y,z doubles, yRot, xRot floats, flags byte. rot (28): yRot, xRot, flags byte. status_only (29): flags byte.
- keep_alive (24): long. pong (39): int.
- player_action (36): action VarInt (0 start destroy, 1 abort, 2 stop, 3 drop all, 4 drop item, 5 release use item, 6 swap offhand), Position, direction byte (unsigned), sequence VarInt.
- player_command (37): entity id VarInt, action VarInt (0 press shift, 1 release shift, 2 stop sleeping, 3 start sprint, 4 stop sprint, 5 start riding jump, 6 stop riding jump, 7 open inventory, 8 start fall flying), data VarInt.
- set_carried_item (47): short slot 0..8.
- set_creative_mode_slot (50): short slot (1..45 valid for inventory menu; hotbar 0 = 36), item stack: VarInt count (0 = empty), VarInt item registry id, VarInt added-components count, VarInt removed-components count (+ component data). Count must not exceed the max stack size.
- swing (54): hand VarInt.
- use_item_on (56): hand VarInt, Position, direction VarInt, cursor x,y,z floats (offset inside the block, 0..1), insideBlock bool, sequence VarInt. Server rejects when the cursor is more than 1.0000001 from the block centre on any axis, when the block AABB is 5.5 or more from the eye, when y >= max build height, or while a teleport is pending.
- use_item (57): hand VarInt, sequence VarInt, yRot float, xRot float.
- chat (6): message string (max 256), timestamp long (epoch millis), salt long, optional signature (bool + 256 bytes), lastSeen update: VarInt offset + 3 bytes fixed bitset (20 bits). chat_command (4): command string (no leading slash), unsigned.
  With enforce-secure-profile=true an unsigned chat message is refused with a system message (not a kick); unsigned commands work unless the command has signable arguments.
- client_command (9): action VarInt (0 perform respawn, 1 request stats).
- chunk_batch_received (8): float desiredChunksPerTick.

Play, clientbound:
- login (43): int entity id, bool hardcore, list of dimension keys, VarInt maxPlayers, VarInt viewDistance, VarInt simulationDistance, bool reducedDebug, bool showDeathScreen, bool limitedCrafting,
  then spawn info (dimension type holder VarInt, dimension key, long seed, byte gameType, byte previousGameType, bool isDebug, bool isFlat, optional last death position, VarInt portalCooldown), bool enforcesSecureChat.
- player_position (64): x,y,z doubles, yRot, xRot floats, relative flags byte, VarInt teleport id.
- keep_alive (38): long. ping (53): int. disconnect (29): network NBT component.
- block_update (9): Position, VarInt block state id. block_changed_ack (5): VarInt sequence (sent at the start of the next server tick for the highest sequence seen).
- section_blocks_update (73): long section position (x 22 bits << 42 | z 22 << 20 | y 20), VarInt count, then per entry a VarLong: state id << 12 | x << 8 | z << 4 | y (local 0..15).
- chunk_batch_start (13, empty) / chunk_batch_finished (12, VarInt count).
- level_chunk_with_light (39): int chunkX, int chunkZ, heightmaps NBT, VarInt size + chunk section bytes (per section: short non-air count; block palette container: byte bits, palette (single: VarInt id; linear/hash: VarInt length + VarInts; global: none), VarInt long count + longs; then the biome container the same way), VarInt block entity count (each: packed xz byte, short y, VarInt type, NBT), light data (4 bit sets as long arrays, then two lists of 2048-byte arrays).
  Block palettes: 1-4 bits use a linear palette of 4 bits; 5-8 bits hash palette; more uses the global palette with ceil(log2(26684)) = 15 bits per entry.
- set_health (93): float health, VarInt food, float saturation. (Respawn needed after death: client_command 0.)

## 4. What the planner/simulator must assume

1. Block updates for the clicked block and the neighbour across the clicked face are sent immediately after every use_item_on, successful or not. A failed placement shows up as the old state (air).
   Digging answers with a block update on failure, or the break itself (a block update to air) on success.
2. Sequence numbers may share one counter; the ack packet carries the highest sequence handled.
3. Block updates only reach players who track the chunk (view distance, default 2 chunks without client_information).
4. Compression threshold is 256 by default; frames below it have dataLength 0.
